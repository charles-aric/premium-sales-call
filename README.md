# Premium video paywall

One page, a $20 FastSpring checkout, and a video that only plays for people who paid. It runs on Cloudflare Pages with a small KV store. No email service, no npm packages, no FastSpring API credentials, no card on file anywhere. Monthly cost is $0.

## How it works

1. The visitor clicks "Pay $20 to unlock" and pays in the FastSpring popup.
2. FastSpring calls `/api/webhook` on your site. The site checks the signature with your webhook secret and saves the paid order in Cloudflare KV.
3. The popup closes and gives the page an order ID. The page asks `/api/unlock`, which looks the order up in KV and sets a signed cookie. If the webhook has not landed yet, the page keeps asking for up to 90 seconds.
4. `/api/video` streams the video only to browsers with that cookie. The video sits in the site as 20 MB parts with random names, and a blocking route refuses every direct request to them, so there is no link to leak.
5. Each purchase works on 3 devices. A fourth device gets refused, so a shared link stops working fast.
6. The buyer gets a personal link to save. Buyers who lose it use the "Already paid?" form with their email and the order reference from their receipt.
7. A refund in FastSpring fires a second webhook that deletes the order from KV. Access ends at once, even for browsers that already hold a cookie.

## Files

```
public/index.html          the page, edit your copy here
functions/api/webhook.js   receives FastSpring payment and refund notices
functions/api/unlock.js    checks KV for the order, applies the device limit, sets the cookie
functions/api/status.js    tells the page if this browser is already unlocked
functions/api/video.js     streams the video to paid viewers
functions/vparts/          blocks direct requests to the video parts
public/vparts/             the video parts go here
lib/video-manifest.js      describes the parts, generated by the split tool
tools/split-video.html     splits your video, runs locally in your browser
lib/shared.js              cookie signing, webhook signature check, KV helpers
```

## Setup

### 1. FastSpring product and checkout

- Create a one-time product priced at $20, tax category Digital Goods. Leave fulfillment empty. Note the product path.
- Under Checkouts, Popup Checkouts, open "Place on your website" and note the `data-storefront` value. It looks like `yourstore.test.onfastspring.com/popup-yourstore`.

### 2. Edit `public/index.html`

- Set `productPath`, `durationMinutes` and `chapters` in the `window.SITE` block near the top.
- Set `data-storefront` on the FastSpring script tag.
- Rewrite the headline, paragraph and chapter list to match the real video.

### 3. GitHub

- Push this folder to a GitHub repo.

### 4. Add the video

No card needed for this route. Cloudflare Pages and GitHub both cap single files at 25 MB, so the video goes in as 20 MB parts.

- Open `tools/split-video.html` from your computer in Chrome. Pick the video and click the button. You get a set of `.bin` files and one `video-manifest.js`.
- In the GitHub repo, open the `public/vparts` folder, choose Add file, Upload files, and drop in every `.bin` file. Commit.
- Open the `lib` folder and upload `video-manifest.js`, replacing the existing one. Commit.

If you later want R2 instead, create a private bucket, upload the file as `video.mp4`, and bind it to the Pages project as `VIDEO_BUCKET`. The site uses R2 when that binding exists and the parts when it does not. R2 needs a card on file.

### 5. Cloudflare KV

- Open Storage and Databases, then KV, and create a namespace named `premium-video-access`.

### 6. Cloudflare Pages

- Go to Workers and Pages, create a Pages project, and connect the repo. Leave the build command empty. Set the build output directory to `public`.
- Under Settings, add these variables. Mark the two secrets as encrypted.

| Name | Value |
| --- | --- |
| `FS_WEBHOOK_SECRET` | a long random string you make up, 30 characters or more |
| `FS_PRODUCT_PATH` | your product path, same as in index.html |
| `COOKIE_SECRET` | a different long random string, 40 characters or more |
| `ALLOW_TEST_ORDERS` | `true` while testing, delete it before launch |
| `MAX_DEVICES` | optional, defaults to 3 |

- Under Settings, Bindings, add a KV namespace binding named `ACCESS_KV`. The name must match exactly.
- Redeploy after changing variables or bindings. Note your site URL, for example `https://premium-video.pages.dev`.

### 7. FastSpring webhook

- Go to Developer Tools, then Webhooks, and add a webhook.
- Add a URL to it. Set the URL to `https://YOUR-SITE/api/webhook`.
- In the HMAC SHA256 Secret field, paste the same string you used for `FS_WEBHOOK_SECRET`.
- Tick two events, `order.completed` and `return.created`.
- Make sure the webhook receives test orders as well as live ones. FastSpring has a setting for this on the webhook.
- In the popup checkout settings, add your site's domain to the allowed website list.

### 8. Test before launch

1. Pay with a FastSpring test card. The video should appear, usually within a few seconds.
2. If it does not, open the webhook in FastSpring and look at its delivery log. A 401 means the secret does not match. A 500 means the `ACCESS_KV` binding is missing.
3. Copy the personal link, open it in a private window, and confirm it unlocks.
4. Try the "Already paid?" form with the test buyer's email and order reference.
5. Open `/api/video` in a fresh private window. It must answer "Payment required".
6. Open the personal link in four different browsers or private windows. The fourth must be refused.
7. Refund the test order in FastSpring. Reload the page in a browser that was unlocked. The video must lock again. If it does not, send me the `return.created` payload from the delivery log, because the order ID sits in a field I could not confirm against a live account.

### 9. Go live

- Change `data-storefront` to the live URL, without `.test.`
- Delete the `ALLOW_TEST_ORDERS` variable and redeploy.
- Add your custom domain in Pages, add it to the FastSpring popup's allowed list, and update the webhook URL if the domain changed.

## Limits worth knowing

- Unlocking after payment depends on the webhook reaching Cloudflare and KV syncing between locations. It is usually a few seconds and can take up to a minute. The page tells the buyer to keep it open while it waits.
- If your site is down when FastSpring calls, FastSpring retries for up to 7 days, so no payment gets lost.
- A buyer can still share with two friends, since each purchase has 3 device slots. Set `MAX_DEVICES` to 2 if you want it tighter. I would not go to 1, because a buyer who clears cookies or switches from laptop to phone uses a new slot.
- When an honest buyer runs out of slots, open the KV namespace in the dashboard and delete the key `order:THEIR_ORDER_ID`. That resets their devices.
- To give someone free access, there is no button. Send them a 100% coupon in FastSpring, so the order flows through the webhook like any other.
- Nothing on the web stops screen recording.
- Storing the video as parts inside Pages is a workaround. Cloudflare's terms steer video toward its R2 and Stream products. At the volume of a $20 niche video nobody is likely to care, but if this grows to thousands of views, move the file to R2. The code already supports it.
- KV's free tier allows 100,000 reads and 1,000 writes a day. One viewing uses a few hundred reads, so you have room for a few hundred viewings a day. Past that, Cloudflare's paid plan is $5 a month.
